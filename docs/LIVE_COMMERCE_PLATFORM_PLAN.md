# AI-Powered Live Commerce Platform — Agora SA Take-Home

**Canonical implementation plan.** This file is the single source of truth. It merges the original build plan with the review revision that corrected it, and is reconciled against `docs/Agora - SA_Candidate_Assignment.pdf`. ## Context

Build the deliverable for `docs/Agora - SA_Candidate_Assignment.pdf`: a working web prototype that is (1) a multi-category e-commerce storefront, (2) a live-shopping surface with scheduled / live / recorded sessions, host broadcast, and viewer chat, and (3) a voice-first AI shopping assistant that answers from the real catalog, compares products, checks PIN-code serviceability and payment options, and adds items to the cart — with a 20% discount valid **only** while the relevant live session is active, enforced server-side. Plus the required written deliverables (README, architecture diagram, customer journey, responsibility mapping, technology rationale, production considerations).

Three requirements were added by the user after initial scoping and are all in scope:

**A. Big-Billion-Days scale.** The scale-out primitives are _built and proven with a load test_, not merely described. Media topology is **hybrid**: Agora RTC for the interactive viewer tier, Agora Media Push → CDN/HLS for the mass tier, with an automatic one-way switch.

**B. Every optional extension from the assignment, plus a seller dashboard.** Live captions / host transcription; reactions, polls, synchronized product cards and highlighted products; searchable transcript and session summary for recorded events; multi-language voice assistance with captions; real authentication with seller/host roles, wishlists, recommendations and order history; moderation, analytics, observability, personalized offers, and a seller dashboard.

**C. Built to absorb follow-up requirement changes** — higher concurrency, different AI providers, PSTN access, stricter privacy, and changes to the live-session discount and checkout rules. These are built as **configuration and seams**, not hardcoded behaviour. See **Adaptability seams**.

### Sequencing principle (why the stage gates below are ordered this way)

The assignment explicitly prioritizes a functional prototype, the Agora/application boundary, the voice-AI pipeline, and live-discount business logic over production polish. The stage gates therefore prove those four areas _first_, in a working vertical slice, before recommendations, dashboards, privacy automation, multi-provider seams, and secondary engagement features. **This is sequencing, not scope reduction** — every capability in A, B and C is still built, and every stage ends in runnable behaviour rather than scaffolding. Later stages extend the core path; they never postpone it.

The stages are **not independent**. They share session, identity, RTM, event and promotion contracts, so they land in order.

### Scope discipline (the assignment's pragmatic clause, and the user restated it)

> "You may use mock inventory, product, delivery-serviceability, payment, or checkout services where appropriate… Prioritize architecture, real-time integration, voice AI, and business logic."

Depth therefore goes to **architecture boundaries, Agora real-time integration, the voice-AI pipeline, and the promotion/discount business rules**. The commerce engine stays deliberately thin and its mocks are isolated in `apps/server/src/domain/mock/` so the Agora-vs-application boundary and the mock-vs-real boundary are both visible in the source tree:

- **Mocked on purpose:** payment pre-authorization (in-process, 200 ms, deterministic failure for a card ending `0000`, no external call), delivery serviceability (seeded PIN-code table), tax/shipping (out of scope entirely — totals are subtotal minus discount), refunds/returns, seller onboarding approval, fraud checks, and search relevance beyond Postgres full-text.
- **Real, because they are business logic or correctness the assignment grades:** the promotion rule engine, live-session discount eligibility and expiry, atomic stock decrement (no oversell), idempotent writes, server-authoritative pricing, server-authoritative chat moderation, and the AI tool contract.
- **Not built:** an order queue / payment worker pipeline. Checkout is synchronous behind an atomic decrement. The async-fulfilment design is one section in `docs/scale-and-capacity.md`; building it would be exactly the production commerce engine the brief says to skip.

Repo is currently empty except `docs/` and this plan. Everything below is greenfield.

Credentials available: Agora App ID + App Certificate + Customer ID/Secret with **Conversational AI Engine enabled**, and an **OpenRouter** API key. **No** OpenAI/Azure/ElevenLabs vendor key, **no** CDN RTMP ingest or HLS origin, **no** object-storage bucket. Every contract below is designed to be demonstrable with exactly those credentials, and anything that is not is labelled `unverified — <missing prerequisite>` rather than claimed.

### Agora Conversational AI Engine (ConvoAI) — REST v2

- Base `https://api.agora.io/api/conversational-ai-agent`; auth `Authorization: Basic base64(CUSTOMER_ID:CUSTOMER_SECRET)`.
- `POST /v2/projects/{appid}/join` → `{agent_id, create_ts, status:"RUNNING"}`; `POST /v2/projects/{appid}/agents/{agentId}/leave` (empty body, empty 200); `GET …/agents/{agentId}`; `POST …/agents/{agentId}/interrupt` `{}`; `POST …/agents/{agentId}/speak` `{text ≤512B, priority, interruptable}`; `POST …/agents/{agentId}/update` (`llm.params` is a full overwrite).
- `llm.vendor:"custom"` + `llm.style:"openai"` ⇒ Agora POSTs an **OpenAI-compatible `/chat/completions` with `stream:true`**. **Non-streaming responses are rejected.** Reply with `data: {chat.completion.chunk}\n\n` frames ending in `data: [DONE]\n\n`.
- **`llm.url` is POSTed verbatim** — Agora does not append `/chat/completions`. Arbitrary path segments and query strings both appear in official examples.
- **`llm.headers`** exists to "pass business-specific information such as custom fields or tenant identifiers"; engine headers win on conflict. This is the supported correlation and authentication channel.
- Body Agora sends: `context`, `model`, `messages` (plus `turn_id` from 0 and `timestamp` ms when `vendor:"custom"`), `tools`, `tool_choice`, `parallel_tool_calls`, `stream`, `stream_options`, `modalities`, `response_format`. `channel` / `agent_id` are **not** body fields, and the auth-header format used for `llm.api_key` is **undocumented** — do not depend on either.
- **`credential_mode: "managed" | "byok"`** per module on `asr`, `llm`, `tts` (default `byok`; top-level `preset` deprecated). **Managed TTS supports only `minimax` (`speech-2.6-turbo`/`speech-2.8-turbo`) and `openai` (`tts-1`)**. ElevenLabs is BYOK-only and Agora's docs require a _paid_ ElevenLabs plan. Managed mode is why this project needs no TTS vendor key at all.
- ASR vendor `ares` (default) needs no customer key: `{"asr":{"vendor":"ares","language":"en-US"}}`. **The current ARES supported-language reference lists `en-US`, `hi-IN` and `es-ES`**, so multi-language voice is a supported configuration, not a hope. Other ASR vendors: `microsoft, deepgram, openai, google, gemini, amazon, assemblyai, sarvam, xai`. TTS vendors: `amazon, cartesia, deepgram, elevenlabs, fishaudio, generic_http, google, gradium, humeai, microsoft, minimax, mistral, murf, openai, rime, sarvam, typecast, xai`.
- `remote_rtc_uids`: **"Currently, only one user ID is supported."** One agent serves one viewer ⇒ per-viewer AI means per-viewer channel + agent.
- **Concurrency cap: 20 PCU per App ID by default** ("…limited to 20. If you need to increase this limit, contact technical support"). Errors `422 ResourceQuotaLimitExceeded`, `429`. Pricing $0.10/min audio task (first 300 min free), same for BYOK.
- `geofence.area ∈ {GLOBAL, NORTH_AMERICA, EUROPE, ASIA, INDIA, JAPAN}`. `idle_timeout` default 30 s; 72 h hard session cap; prefer explicit `/leave`.
- Transcripts: `advanced_features.enable_rtm:true` + `parameters.data_channel:"rtm"`. The agent publishes to an **RTM message channel named exactly the RTC channel name**. Payload `{object, text, start_ms, duration_ms, language, turn_id, stream_id, user_id, words}`; `object` ∈ `user.transcription` (+`final`), `assistant.transcription` (+`quiet, turn_seq_id, turn_status`), `message.interrupt`, `message.metrics`, `message.error`.
- Client helper npm **`agora-agent-client-toolkit@2.9.1`** — the version this plan pins. It exports **both `AgoraVoiceAI` and `ConversationalAIAPI`**; this plan uses `AgoraVoiceAI`. Usage: `const api = await AgoraVoiceAI.init({rtcEngine, rtmEngine, renderMode: TranscriptHelperMode.TEXT})`; `api.on(AgoraVoiceAIEvents.TRANSCRIPT_UPDATED, …)`; `api.on(AgoraVoiceAIEvents.AGENT_STATE_CHANGED, …)`; `api.subscribeMessage(channelName)`. **Bind handlers against the installed `2.9.1` type signatures** — do not assume the older two-argument `TRANSCRIPT_UPDATED` shape; the compiler is the arbiter (test A8 compiles it). **`subscribeMessage` only binds listeners — the app must itself `login({token})` and `subscribe(rtcChannelName, {withMessage:true, withPresence:true})`** or zero transcripts arrive. In this plan that is `RtmProvider`'s job, never the hook's.
- `AgoraRTC.setParameter("ENABLE_AUDIO_PTS_METADATA", true)` before `createClient` is needed only for word-by-word render mode, not for `TranscriptHelperMode.TEXT`.
- With `enable_rtm:true`, the **agent's** `properties.token` must carry **both RTC and RTM privileges**: `RtcTokenBuilder.buildTokenWithRtm(appId, cert, channel, account, role, tokenExpire, privilegeExpire)`. Token `account` must equal `agent_rtc_uid`; a numeric uid string (`"1001"`) works with `enable_string_uid:false`. Do **not** use `agent_rtc_uid:"0"` with a token.
- Deprecated, do not use: `advanced_features.enable_aivad`, flat `turn_detection.*_ms`, top-level `preset`.
- Webhooks (Console → Notifications): ConvoAI events **101 agent joined, 102 agent left, 103 dialogue history, 110 agent error, 111 performance metrics, 201/202 call status**. HMAC-SHA1 `Agora-Signature` / HMAC-SHA256 `Agora-Signature-V2`; return 200 within 10 s; 3 retries then dropped; Agora states core flows must not depend on NCS.
- Reference repos: `AgoraIO-Community/Agora-Conversational-AI-Ecommerce-Demo` (`app/api/agora/start-agent/route.ts`), `AgoraIO-Community/Conversational-AI-Server-Sample` (`node/custom_llm/custom_llm.js`), `AgoraIO-Conversational-AI/agent-client-toolkit-ts` (current imports, RTM peer dependency, init and subscription order).

### Agora scale limits (drive the architecture doc and the code's guard rails)

- **1,000,000 concurrent users per channel**, unlimited channels, **128 concurrent hosts per channel**, each client subscribes to at most **50 hosts**.
- **Per-project regional quota benchmark: PCU 10,000 and bandwidth 10 Gbps** per region; above that, contact Agora support. This, not the 1 M ceiling, is the real CDN-offload trigger.
- Audience billing roles: _Interactive Live Audience_ (ultra-low latency, priced like a host, $0.99/1,000 std audio min) vs *Broadcast Streaming Audience* (0.57×/2×/4.57× conversion, $0.59 audio, $1.99 HD per 1,000 min).
- **Media Push** (per-task object = "Converter"): `POST https://api.agora.io/{region}/v1/projects/{appId}/rtmp-converters`, `region ∈ {cn, ap, na, eu}`; Create/Get/Update/Delete; transcoded (layout, bitrate 1–10000 Kbps) or raw (`rtcStreamUid`); states `connecting|running|failed`. Agora pushes RTMP(S) to **your** CDN; HLS packaging is the CDN's job. Transcoding $7.99/1,000 min HD H.264.
- **Media Gateway** ingests RTMP/SRT into a channel (OBS-grade sellers). **Media Pull** injects online media into a channel.
- **Cross-channel media relay**: `startOrUpdateChannelMediaRelay`, host role only, **max 6 target channels per host**, int UIDs only, activated by support.
- **RTM limits**: subscribers per message channel _unlimited_; **60 msg/s per client**; 32 KB packet; **50 subscribed channels per client**; **20 API calls/s per client**. Account defaults (raisable): **500 REST req/s per App ID**, 50,000 concurrent users, 500,000 DAU, **50,000 users per single channel**. Billing counts one send to N subscribers as 1+N messages — mega-room fan-out dominates cost.
- **Cloud Recording**: **PCW 50** concurrent workers default, **10 QPS per App ID**, per-task stream caps by region (EU: SD 50 / HD 30 / FHD 10), 1080p30 cap; dual domains `api.agora.io` / `api.sd-rtn.com`; HA migration ≤ 90 s; NCS events 40 recorder_started, 11 session_exit, 1 error, 12 failover, 31 uploaded.
- Observability: Agora Analytics (Data Insights / Real-time monitoring / Call Inspector / Alerts / Datadog) plus a RESTful Analytics API. Cloud Proxy for restricted networks. Geofencing on RTC, RTM and ConvoAI (`INDIA` on all three).
- Agora publishes **no numeric RTC→CDN cutover**. Defensible statement: interactive tier on RTC up to the project's 10 k PCU / 10 Gbps regional quota (raisable toward the 1 M/channel ceiling); passive tier via Broadcast Streaming audience role or Media Push → CDN.

### OpenRouter + tunnel

- `POST https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer <key>`; `HTTP-Referer` / `X-OpenRouter-Title` optional. Official `openai` npm SDK (7.9.0, **requires Node ≥ 22**) works via `baseURL`.
- Fully OpenAI-compatible `tools` / `tool_choice` / `parallel_tool_calls`; streamed tool calls arrive on `choices[0].delta.tool_calls` and must be accumulated **by `index`** (first fragment carries `id` + `function.name`, later fragments append `function.arguments`), terminal chunk `finish_reason:"tool_calls"`.
- Quirks a strict SSE consumer must handle: `: OPENROUTER PROCESSING` comment keepalives (skip `:`-prefixed lines); the final usage chunk **repeats `finish_reason`** in a choice with an empty delta (unlike OpenAI's empty `choices`); mid-stream errors arrive as HTTP-200 SSE data events with a top-level `error` and `finish_reason:"error"`.
- Verified tool-capable, low-latency model IDs: `openai/gpt-4o-mini`, `google/gemini-2.5-flash`, `anthropic/claude-haiku-4.5`. **`anthropic/claude-3.5-haiku` has zero active endpoints — do not use.**
- **Cloudflare quick tunnels officially do not support SSE** — unusable for the custom-LLM callback. **Use ngrok** (`brew install ngrok`; free-account authtoken required; verified unbuffered SSE passthrough). Express `compression` buffers SSE — exclude the streaming routes; set `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, `res.flushHeaders()` immediately, and emit keepalive comments.

### The OpenAI-compatible tool-message contract (binding on the proxy)

Per the official custom-LLM guide and the OpenAI-compatible message schema: within one model round, after `finish_reason:'tool_calls'`, the conversation **must** be extended with the complete **assistant** message carrying its `content` plus the ordered `tool_calls: [{id, type:'function', function:{name, arguments}}]`, and **only then** one `{role:'tool', tool_call_id, content}` message per result, in the same order. Appending tool results without the preceding assistant message is a protocol violation; providers reject or mis-handle it.

## Architecture decisions (locked)

1. **Two RTC channels per viewer, never one.** ConvoAI's agent audio must be private, so the AI conversation runs in its own channel `ai-<conversationId>` (viewer publishes mic as host, agent joins with `remote_rtc_uids:[viewerUid]`) while the viewer stays an **audience** member of `live-<sessionSlug>`. Two `IAgoraRTCClient` instances in one page, each with its own numeric uid. While a conversation is open the live stream's remote audio is ducked with `remoteAudioTrack.setVolume(15)`, restored to 100 on stop. This is what satisfies "private voice conversation … while still tuned into the Live Stream".
2. **Exactly one RTM (Signaling) client per browser session.** `apps/web/src/realtime/RtmProvider.tsx` is the only RTM owner: it constructs `new RTMClient(appId, 'user-<users.id>')` once, logs in with a standalone RTM token from `POST /api/rtm/token`, renews that token before expiry, and exposes **reference-counted** `subscribe(channel)` / `release(channel)`. Chat and the ConvoAI transcript channel are both subscriptions on that single client; `AgoraVoiceAI.init({rtcEngine, rtmEngine})` receives it. Agora documents one Signaling client instance per app/client, and two clients would also double the RTM account concurrency footprint. No hook constructs an RTM client.
3. **Agora's LLM is our own backend.** `llm.vendor:"custom"` pointing at `${PUBLIC_API_URL}/api/ai/convo/{conversationId}/chat/completions`. Our proxy owns the tool list and executes tools in-process against the commerce domain, streaming only assistant text back. Agora never sees the catalog and never calls a business API directly. **Callback authentication is a per-conversation HMAC**, not a global shared secret: `X-Convo-Expires: <unix-seconds>` plus `X-Convo-Signature: base64url(HMAC-SHA256(CONVO_LLM_SHARED_SECRET, "<conversationId>.<expires>"))`, verified in constant time against the conversation id in the path. `X-Convo-Id` carries the same id for logging. The HMAC key never leaves the server; a leaked signature is scoped to one conversation and expires.
4. **Managed-mode ASR and TTS — no vendor key exists in this project.** ASR `ares` (`en-US`, `hi-IN`, `es-ES`, all in the supported-language reference). TTS `credential_mode:"managed"`, `vendor:"openai"`, `model:"tts-1"`. **If the project rejects that managed vendor, the fallback is Agora-managed MiniMax `speech-2.8-turbo` — still managed, never BYOK**, because there is no OpenAI key to fall back to. LLM is our proxy → OpenRouter.
5. **Discounts are rules in the database, never constants in code.** The 20% live-session offer is a seeded `promotions` row with `conditions.requiresLiveSession = true`; one pure evaluator in `packages/shared/src/promotions.ts` decides what applies. Changing the percentage, switching it to a flat amount, restricting it to a category, making it stackable, or adding a checkout rule is a data change plus an admin API call — no redeploy.
6. **Checkout policy is data too.** Minimum order value, COD ceiling, EMI floor, allowed payment methods and pincode gating live in a `checkout_policies` row read by both the checkout endpoint and the AI's `get_payment_options`, so they cannot disagree.
7. **Live eligibility is resolved server-side from relational truth, once.** One function, `resolveLineContext(userId, line, now)` — where `line = {variantId, quantity, surface, liveSessionId, orderSubtotalMinorUnits}` — is the only path by which cart, checkout and AI tools decide whether a line is live-eligible. A line qualifies **only if all** hold at evaluation time: the session exists, `status='live'`, the product is attached in `liveSessionProducts`, and the variant belongs to that product. Mismatch at add time → `400 invalid_live_session_product`; a session that ended or lost the attachment is ineligible at cart read and at checkout, with notice `live_discount_expired`. Prices always come from `productVariants` at evaluation time; `cartItems.unitPriceMinorUnits` is a display snapshot and never authoritative.
8. **Delivery tier is one-way session state, not a per-join decision.** Media Push starts with the session. When the pruned viewer count first reaches `RTC_TIER_MAX_VIEWERS` **and** the converter/HLS origin is ready, a Redis compare-and-set flips `session:<id>:deliveryTier` from `rtc` to `cdn`, the winner publishes `session.delivery_tier_changed`, and every current audience client starts HLS **before** leaving the live RTC channel. It never flips back during a session, so the threshold cannot oscillate; new joiners simply read the stored tier.
9. **Everything horizontally scalable.** API processes are stateless; shared state is Postgres or Redis; recordings live on a shared volume, never in a replica's local path. Cross-replica SSE fan-out rides Redis pub/sub with **one subscriber connection per API process**. Two API replicas run behind nginx in the load-test stack and the k6 suite proves it. The **single** background process owns all timers, so no aggregate is emitted twice.
10. **Admission control for ConvoAI.** The documented default is 20 concurrent agents per App ID. A Redis lease semaphore enforces `CONVOAI_MAX_CONCURRENT_AGENTS`; on exhaustion the client degrades to the **same tool-calling assistant over text**, so the journey never dead-ends. Text is an explicitly-labelled degraded transport — never presented as proof of voice or of multi-language voice.
11. **Chat is server-mediated, which is what makes moderation authoritative.** Viewers never publish to RTM. `POST /api/sessions/:id/chat` authenticates, rejects muted/banned users immediately, applies rate and profanity rules, persists the accepted text, then publishes the canonical envelope through the Signaling REST messaging API as the fixed RTM account **`chat-service`**. Clients render a chat event **only** when its publisher is `chat-service`; user RTM tokens are bound to `user-<id>`, so a client cannot impersonate the publisher. The cost is one network hop before a message appears — accepted deliberately, because a mirror-after-publish design cannot enforce a ban until the next token refresh.
12. **Chat shard count is frozen at session start.** `liveSessions.expectedPeakViewers` and `liveSessions.chatShardCount` are persisted; `chatShardCount = clamp(ceil(expectedPeakViewers / RTM_CHAT_SHARD_TARGET), 1, 49)` is computed **once**, at the `scheduled → live` transition, and a viewer's shard is `sha256(userId) % chatShardCount` forever. Recomputing the modulus from a live viewer count would silently re-route users mid-session. The host subscribes to that immutable set (≤49, leaving headroom under RTM's 50-channels-per-client limit) — and because a client may make only **20 API calls/s**, the host console subscribes in paced batches, so a 49-shard session takes ≈3 s to become fully subscribed and the UI shows "joining chat" until it is. A host message is fanned out by the **backend** through the Signaling REST API (500 req/s per App ID) to all shards in bounded batches, never from the host client.
13. **High-frequency signals are aggregated, not fanned out.** Reactions increment a Redis counter and broadcast as a 1 Hz aggregate over SSE instead of one RTM message per tap; poll votes are server-owned for the same reason. Both 1 Hz flushes run **only** in the background process.
14. **Global rules are admin-owned; sellers own their sessions.** Global promotions (including `LIVE20`) and checkout policy are edited at `/admin/promotions` and `/admin/checkout-policy` behind `requireRole('admin')`. The seller dashboard owns session scheduling/hosting, products and inventory, moderation history and session analytics — it never calls an endpoint that would reject a seller.
15. **Privacy is a runtime mode, not a policy document.** `PRIVACY_MODE=standard|strict` changes what is persisted; PII redaction, retention purging and subject erasure are implemented, and data residency is pinned through Agora's geofence parameters.
16. **Commerce stays thin — but the payment boundary is honest.** Pre-authorization is a labelled in-process mock that performs no external call. It runs **before** the stock transaction is opened, so no database transaction or row lock is ever held across its 200 ms delay. A real provider would replace it with authorize → reserve → capture/void plus an expiry reconciler; transaction rollback cannot undo an external charge and this plan never pretends otherwise.
17. **Deferred work is a durable stream, not an unspecified queue.** Session summaries go to the Redis stream `jobs:session-summary` with a consumer group; the background process also consumes `analytics:events`, expired AI leases, recording polls, aggregate flushes and retention. Each entry is acknowledged only after its durable write. This is a Redis primitive already in the stack — still no job-queue dependency.

### Promotion evaluator contract (`packages/shared/src/promotions.ts`)

Pure, exhaustively unit-tested, and the **only** place discount semantics exist.

```ts
export type PromotionCondition = {
  surfaces?: ('live' | 'replay' | 'browse')[];
  requiresLiveSession?: boolean;
  categorySlugs?: string[];
  productIds?: string[];
  sellerIds?: string[];
  minLineMinorUnits?: number;
  minOrderMinorUnits?: number;
  userSegments?: ('first_order' | 'has_wishlisted' | 'loyalty_3plus')[];
  maxRedemptionsPerUser?: number;
};
export type Promotion = {
  id: string;
  code: string;
  label: string;
  kind: 'percent' | 'flat';
  value: number;
  priority: number;
  stackable: boolean;
  conditions: PromotionCondition;
  validFrom?: string;
  validUntil?: string;
  active: boolean;
};
export type LineContext = {
  surface: 'live' | 'replay' | 'browse';
  liveEligible: boolean;
  liveSessionId: string | null;
  categorySlug: string;
  productId: string;
  sellerId: string;
  unitPriceMinorUnits: number;
  quantity: number;
  orderSubtotalMinorUnits: number;
  userSegments: string[];
  redemptionsByPromotionId: Record<string, number>;
  now: Date;
};
export function evaluatePromotions(
  all: Promotion[],
  ctx: LineContext,
  maxTotalPct: number,
): {
  grossMinorUnits: number;
  discountMinorUnits: number;
  netMinorUnits: number;
  applied: { code: string; label: string; minorUnits: number }[];
  suppressed: {
    code: string;
    label: string;
    reason: 'not_stackable' | 'capped' | 'redemption_limit';
  }[];
};
```

Semantics, fixed here so nothing is left to the implementer:

1. Filter by `active`, the validity window, and every condition **except `maxRedemptionsPerUser`**. `requiresLiveSession` consults `ctx.liveEligible`, which only `resolveLineContext` may set. `maxRedemptionsPerUser` is deliberately checked _after_ selection, so an exhausted promotion is reported rather than silently vanishing.
2. **`stackable:false` means the promotion cannot combine with _any_ other promotion.** Build exactly two classes of candidate: (a) each eligible non-stackable promotion **alone**, and (b) the combined set of **all** eligible stackable promotions.
3. Choose the candidate with the **largest realized discount**; tie-break on the **highest priority contained** in the candidate; final tie-break on the **lexicographically smallest promotion code**. The result is deterministic.
4. Apply `maxTotalPct` of gross to the winning candidate, trimming the **lowest-priority stackable** contributions first; when the candidate is a single non-stackable promotion there is nothing to trim, so clamp its own `minorUnits` down to the cap and report it as `capped`.
5. A promotion whose `maxRedemptionsPerUser` is exhausted is dropped from the winning candidate and reported as `redemption_limit`; every other eligible-but-unapplied promotion appears in `suppressed` as `not_stackable` or `capped`. Flat values clamp to line gross.

Consequence to expect in tests and demos: seeded `LIVE20` (non-stackable) **does not** combine with `WISHLIST5`; flipping `LIVE20.stackable` to `true` is precisely what permits the loyalty combination.

    1. Validate against the policy and recompute all pricing server-side through `resolveLineContext` + `evaluatePromotions` (never trust the client).
    2. **`preauthorize` — outside any transaction.** Failure ⇒ `402 payment_declined`, no order row, no stock mutation.
    3. **One short transaction:** revalidate policy, current `productVariants` prices, live eligibility and redemption caps; decrement every line atomically with `UPDATE product_variants SET stock = stock - $qty WHERE id = $id AND stock >= $qty RETURNING stock` (zero rows ⇒ abort `409 out_of_stock`); insert `orders` / `orderItems` (with per-line `liveSessionId`) / `promotionRedemptions`; clear the cart.
    4. If the revalidated total differs from the pre-authorized amount — most likely because the session ended mid-checkout and `LIVE20` dropped — abort, `voidPreauthorization`, and return `409 pricing_changed` with the new totals so the client re-confirms. Any other abort (including `409 out_of_stock`) follows the same void-then-return path. No read-then-write anywhere, so overselling is structurally impossible, and **no lock is ever held across the 200 ms delay**.
  - `GET /api/orders` (history) and `GET /api/orders/:id`.
  - `docs/scale-and-capacity.md` documents the production replacement — authorize → stock reservation → capture/void with an expiry reconciler — and states plainly that a database rollback cannot undo an external payment call.

### Stage 3 — Core live-commerce vertical slice

**Gate, in one run: the seller starts a session; a shopper watches over Agora RTC, sends server-mediated chat, sees the featured product, opens the private AI channel while live audio ducks, asks a catalog question, invokes `add_to_cart`, receives the live discount, checks out, watches the session end, loses the discount, and replays the browser-recorded video.** This is the assignment's core journey and the first complete demo.

- **Session lifecycle.** `routes/sessions.ts`: `GET /api/sessions?status=`; `GET /api/sessions/:slug` (session + products + `deliveryTier` + viewer count + open poll); `POST /api/sessions`, `PATCH /api/sessions/:id`, `POST /api/sessions/:id/products` (seller); `POST /api/sessions/:id/start`; `POST /api/sessions/:id/end`; `POST /api/sessions/:id/join`; `POST /api/sessions/:id/heartbeat`; `POST /api/sessions/:id/pin {productId}`.
  - **Start** is conditional and idempotent: `UPDATE live_sessions SET status='live', startedAt=now(), chatShardCount=$n WHERE id=$id AND status='scheduled' RETURNING *`. Only the request that wins the transition writes `session:<id>:status`, freezes `chatShardCount` (decision 12), publishes `session.status_changed`, and starts recording, RTT and Media Push. Each side service records its **own** `recordingStatus` / `rttStatus` / `mediaPushStatus` (with `recordingError` for the reason) and a failure there **never** rolls back a working RTC session.
  - **End** is the mirror: `… SET status='ended', endedAt=now() WHERE id=$id AND status='live' RETURNING *`. The winner publishes, runs the cart-invalidation fan-out, appends to `jobs:session-summary`, and performs **idempotent best-effort cleanup** of recording/RTT/Media Push after the database transition. Repeated or concurrent calls create and stop each Agora side service at most once (test A7).
  - `POST /api/sessions/:id/join` returns `{deliveryTier, rtcChannel, rtcToken, uid, chatChannel, shardIndex, chatShardCount, hlsUrl?, hlsOriginKind?, captionsEnabled, recordingConsentRequired}`. It **does not** return an RTM identity — the browser already has one from `RtmProvider` (decision 2).
  - Presence: Redis sorted set `session:<id>:viewers` scored by epoch-ms; `ZADD` on 10 s heartbeat; `ZREMRANGEBYSCORE` prune on read; `viewerCount = ZCARD`; `peakViewers` updated; `session.viewers_changed` debounced to 1 Hz **from the background process**.
  - When a session becomes `ended`, `domain/sessions.ts` publishes `session.status_changed` **and** `cart.updated` to every user holding a line bound to that session (one indexed query), so open carts lose the discount without a refresh.
- **Host and viewer surfaces.** `HostConsole.tsx`: preview, consent acknowledgement, **Go live**, pin/unpin, viewer count, recording + caption indicators, **End session** (poll composer and moderation panel land in Stage 5). - **Server-mediated chat** (decision 11). `domain/chat.ts` computes `shardIndex = sha256(userId) % session.chatShardCount` from the **frozen** count. Shard channels are named `chat-<slug>-<shardIndex>`, so viewer, host and backend all derive the full set from `slug` + `chatShardCount` with no extra round trip. `POST /api/sessions/:id/chat {messageId, text}`: authenticate → reject `muted`/`banned` from Redis `session:<id>:bans` / `:mutes` with `403 chat_blocked` → rate limit (120/min) → profanity score (`flagged`) → persist `chatMessages` → publish the canonical envelope through the Signaling REST messaging API as `CHAT_SERVICE_RTM_USER` → emit analytics. Envelope: `{"v":1,"type":"chat"|"moderation","messageId","sessionId","shardIndex","userId","displayName","role","text"?,"ts"}`; unknown `type` is ignored so the format can grow. `useChat.ts` subscribes to its own shard through `RtmProvider` and **renders only events whose publisher is `chat-service`**; everything else is dropped. A host message is fanned out by the backend to all `chatShardCount` shards in bounded batches capped by the ≤500 REST req/s per-App-ID budget (the 20 calls/s ceiling is a _client_ limit and does not constrain this server path); `chat_rest_publishes_total` makes the rate observable.
- **Synchronized product cards and highlights.** The host's `pin` sets `pinnedAt` and publishes `session.product_pinned`; viewers in both tiers move that card to the top with a "Featured now" highlight, and the AI panel's context product switches to it. `GET /api/sessions/:id/products` returns the ordered rail with `isFeatured`/`pinnedAt` so late joiners render correctly without waiting for an event. - **Voice AI assistant — the core of the exercise.**
  - **Lifecycle** — `ai/conversations.ts`, `routes/ai.ts`: `POST /api/ai/conversations {surface, liveSessionId?, productId?, language?}` allocates uids, inserts the row, computes `callbackExpiresAt = now + CONVO_CALLBACK_TTL_SECONDS`, mints the **viewer's private-channel RTC publisher token** for `ai-<conversationId>`, and returns `{conversationId, rtcChannel, rtcToken, viewerUid, agentUid}` — **no RTM token and no second RTM identity**; the browser reuses `RtmProvider`.   - **Admission control** — `ai/admission.ts`: `acquireSlot` runs a Lua script that prunes expired leases from sorted set `ai:agents` and `ZADD`s when `ZCARD < CONVOAI_MAX_CONCURRENT_AGENTS`. Lease TTL = `CONVOAI_IDLE_TIMEOUT_SECONDS + 60`, refreshed by heartbeat; a 30 s sweeper in the background process calls `leave` for expired-but-running conversations and for any conversation older than `CONVO_CALLBACK_TTL_SECONDS`. Transcripts carry the payload's `language` and the panel labels them. Changing language mid-conversation restarts the agent (ConvoAI `update` does not cover `asr.language`).
  - **ConvoAI join body** — `agora/convoai.ts` builds exactly:
    ```jsonc
    {
      "name": "convo-<conversationId>",
      "properties": {
        "channel": "ai-<conversationId>",
        "token": "<mintAgentRtcRtmToken('ai-<conversationId>', agentUid)>",
        "agent_rtc_uid": "<agentUid>",
        "remote_rtc_uids": ["<viewerUid>"],
        "enable_string_uid": false,
        "idle_timeout": <CONVOAI_IDLE_TIMEOUT_SECONDS>,
        "advanced_features": { "enable_rtm": true },
        "parameters": { "data_channel": "rtm", "enable_metrics": true, "enable_error_message": true },
        "geofence": { "area": "<CONVOAI_GEOFENCE_AREA>" },
        "asr": { "vendor": "<CONVOAI_ASR_VENDOR>", "credential_mode": "<CONVOAI_ASR_CREDENTIAL_MODE>",
                 "language": "<conversation.language>" },
        "tts": { "credential_mode": "managed", "vendor": "<CONVOAI_TTS_VENDOR>",
                 "params": { "model": "<CONVOAI_TTS_MODEL>", "voice": "<CONVOAI_TTS_VOICE>", "speed": 1 } },
        "llm": {
          "vendor": "custom", "style": "openai",
          "url": "<PUBLIC_API_URL>/api/ai/convo/<conversationId>/chat/completions",
          "api_key": "<signature>",
          "headers": { "X-Convo-Id": "<conversationId>",
                       "X-Convo-Expires": "<expires>",
                       "X-Convo-Signature": "<signature>" },
          "system_messages": [{ "role": "system", "content": "<buildSystemPrompt(conversation)>" }],
          "greeting_message": "<contextual greeting in the chosen language>",
          "failure_message": "I couldn't reach the catalog just now. Please try again.",
          "max_history": 24,
          "params": { "model": "<LLM_MODEL>", "temperature": 0.4, "max_tokens": 400 }

    ```
    `signature = base64url(HMAC-SHA256(CONVO_LLM_SHARED_SECRET, conversationId + '.' + expires))`. It is placed in `llm.api_key` only because Agora may require a non-empty key; **authorization never reads `Authorization`** — only the two custom headers. Managed TTS sends no `api_key` and no vendor `base_url`. The MiniMax fallback swaps `vendor`/`model` (its voice field name is pinned by smoke check S6) and stays `credential_mode:"managed"`. `buildSystemPrompt` states role, surface, featured product, reply language, the **currently configured** live-offer rule read from `promotions` via the evaluator (so a discount change is reflected in what the agent says), the non-stacking rule, and an instruction to use tools rather than guess.
  - **Custom-LLM proxy** — `ai/completionsRoute.ts`, `POST /api/ai/convo/:conversationId/chat/completions`:
    1. **Authorize**: constant-time-verify `X-Convo-Signature` against `HMAC-SHA256(secret, "<path conversationId>.<X-Convo-Expires>")`, reject a past or absurdly-future `expires`, then load the conversation (404 if unknown, 401 on any signature/expiry failure).
    2. Bypass `compression`; set `text/event-stream`, `no-cache`, `X-Accel-Buffering: no`; `res.flushHeaders()`; start a 5 s keepalive comment timer. Register `res.on('close')` → `AbortController.abort()` **and** `clearInterval` so a disconnected Agora client cannot leave provider work or timers running.
    3. Prefix Agora's `messages` with a **freshly computed live-context system message** on every request: current session status, whether a live promotion applies _right now_ (via `resolveLineContext` + `evaluatePromotions`, never a constant), the pinned product, the shopper's eligible offers, and their default pincode.
    4. Loop, max 3 rounds: `provider.streamChat({model, messages, tools: SHOPPING_TOOLS, toolChoice:'auto'})`. Accumulate `delta.tool_calls` **by `index`**. Forward text content to Agora immediately as `chat.completion.chunk` frames. On `finish_reason:'tool_calls'`: **append the complete assistant message with its `content` and ordered `tool_calls`, then execute, then append one `{role:'tool', tool_call_id, content}` per result in the same order** — the contract stated under _Verified external facts_. **Read-only tools may run in parallel; `add_to_cart` and `add_to_wishlist` execute serially in model order.** Every argument object is validated with the shared zod schema, and each mutating result is written to `aiToolCalls` keyed `(conversationId, turnId, name, argsHash)`; a retried Agora callback — which re-runs the model and therefore produces a _new_ `toolCallId` for the same intent — replays the stored result instead of mutating the cart twice.
    5. Finish with a `finish_reason:'stop'` chunk then `data: [DONE]\n\n`. On any error, **record a structured `ai_error` analytics event and log line first**, then stream one graceful sentence rather than an HTTP error, because Agora expects SSE.
    6. Persist messages to `aiMessages` (subject to `PRIVACY_MODE` and PII redaction); record `llm_latency_seconds{provider}`, `tool_latency_seconds`, analytics events.

    _Read-only:_ `search_products {query, category?, max_price_inr?, min_rating?, limit?}` · `get_product_details {product_id}` · `compare_products {product_ids[2..4]}` · `check_delivery {pincode, product_id}` (unknown pincode → `{serviceable:false, reason:'unknown_pincode'}`) · `get_payment_options {product_id?, pincode?}` (the same function checkout uses) · `get_live_offer {}` · `get_personalized_offers {product_id?}` · `recommend_products {based_on?, product_id?, limit?}` · `get_cart {}`.

### Stage 5 — Optional engagement extensions

**Gate: every optional extension in the assignment is exercisable in the running app.**

- **Reactions:** `POST /api/sessions/:id/reactions {emoji}` (120/min/user) → `HINCRBY session:<id>:reactions emoji 1`; the **background process** emits `session.reactions {counts, deltas}` at 1 Hz; emoji animate client-side from the delta.
- **Polls:** `POST /api/sessions/:id/polls {question, options[]}` → `poll.opened`; `POST /api/polls/:id/vote {optionId}` (one vote per user via the `(pollId,userId)` PK) → counts in Redis, `poll.results` at 1 Hz **from the background process**; `POST /api/polls/:id/close` → `poll.closed`. Results persist for replay and the dashboard.
- **Moderation UI and history:** `POST /api/sessions/:id/moderation {action:'delete_message'|'mute'|'unmute'|'ban', targetUserId?, targetMessageId?}` (host/admin) → writes `chatModeration`, updates Redis `session:<id>:bans` / `:mutes`, publishes `chat.moderated` over SSE **and** a `chat-service` moderation envelope to every shard. Because `POST /chat` consults those keys on every message, a ban takes effect on the **next message**, not the next token refresh; a platform-level ban (`users.bannedAt`, admin-set) additionally refuses `POST /api/rtm/token`, while a session ban deliberately does not, because that token also carries the user's AI transcripts and chat reads. Host console gains the moderation panel and log.
- **Live captions and host transcription (multi-language):** `agora/rtt.ts` — Real-Time STT **v7** `POST /join` with `languages` from `TRANSCRIPTION_LANGUAGES`, `rtcConfig.enableJsonProtocol:true`, `pubBotUid` from the sequence, and `translateConfig` from `TRANSCRIPTION_TRANSLATE_TARGETS`; `POST /leave` on end; gated on `TRANSCRIPTION_PROVIDER=agora` and tracked in `rttStatus`. The host client receives captions on `client.on('stream-message', …)`, inflates with `DecompressionStream('gzip')`, parses JSON, renders the overlay locally, and batches finalized lines to `POST /api/sessions/:id/transcript`. The server re-publishes each finalized line as `session.caption` over SSE so **viewers in both tiers** see captions — the CDN tier cannot receive stream messages at all. Viewers choose a caption language from the available translations. With `TRANSCRIPTION_PROVIDER=off` (default) the AI conversation still has live captions from ConvoAI transcripts and the seeded ended session ships a two-language fixture, so every caption surface is populated.
- **Searchable transcript and session summary:** `GET /api/sessions/:id/transcript?q=` (tsvector) with rows that seek the replay by `startMs`; the background process consumes `jobs:session-summary` and writes `transcriptSummary` via one LLM call when transcript rows exist. `Replay.tsx` gains transcript search, the summary, poll results and chat replay.
- **Multi-language voice + captions:** the ConvoAI language selector from Stage 3 plus RTT `translateConfig` here; the panel and caption overlay label the language of every line.

### Stage 6 — Seller and platform operations

**Gate: a seller runs their business from the dashboard, the platform is observable, and privacy obligations are executable.**

- **Analytics ingestion:** `lib/analytics.ts` `track(event)` pushes to Redis stream `analytics:events`. **`apps/server/src/background.ts`** is the single process that owns every timer: drain `analytics:events` into Postgres in `ANALYTICS_DRAIN_BATCH`-row batches every `ANALYTICS_DRAIN_INTERVAL_MS` (500 rows / 250 ms ⇒ a 2,000 rows/s target), consume `jobs:session-summary` via a consumer group, sweep expired ConvoAI leases, poll Cloud Recording `query` for in-flight recordings, emit the 1 Hz reaction/poll/viewer aggregates, and run the nightly retention purge. Every stream entry is `XACK`'d only after its durable write; `analytics_stream_backlog` is exported.
- `domain/analytics.ts`: per-session `{peakViewers, uniqueViewers, avgWatchSeconds, chatMessages, reactions, pollVotes, aiConversations, aiToolCalls, addToCarts, orders, gmvMinorUnits, conversionRate, discountGivenMinorUnits by promotion code}` (GMV and discount attribution read `orderItems.liveSessionId`), a per-minute viewer time series, and a top-products table attributed to pin windows.
- `routes/seller.ts` (`requireRole('seller'|'admin')`): `GET /api/seller/overview`, `GET /api/seller/sessions`, `GET /api/seller/sessions/:id/analytics`, `GET /api/seller/sessions/:id/moderation` (the Moderation-log data source), `GET /api/seller/products` (inventory + low-stock flags), plus the session scheduling endpoints from Stage 3.
- `apps/web/src/pages/seller/*`: Overview, Sessions (schedule, go live, post-session analytics with `recharts`), Inventory, Moderation log. **The promotions editor lives at `apps/web/src/pages/admin/Promotions.tsx` behind the admin role** and is where the rules-change demo happens (decision 14).
- `domain/recommendations.ts`: `similarProducts(productId)` (same category, nearest price band, rating desc), `recentlyViewed(userId)`, `becauseYouWishlisted(userId)`. Cached per user 60 s. Surfaced on the PDP, home, the empty cart, and the `recommend_products` tool. Personalized offers surface through `get_personalized_offers` and the cart's `suppressed`/`applied` breakdown.
- **Provider registry** — `apps/server/src/ai/providers/`:
  ```ts
  export interface LlmProvider {
    readonly id: string;
    streamChat(req: {
      model: string;
      messages: ChatMessage[];
      tools: ToolSchema[];
      toolChoice?: 'auto' | 'none';
      signal: AbortSignal;
    }): AsyncIterable<LlmChunk>;
  }
  ```
  Three registered implementations, all genuinely used: `openrouter` (adds the optional `HTTP-Referer` / `X-OpenRouter-Title` headers and OpenRouter's SSE hardening — skip `:`-comment lines, ignore the duplicated `finish_reason` on the trailing usage chunk, treat an HTTP-200 frame carrying `error` as a failure), `openai-compatible` (OpenAI/Groq/Together/Azure/vLLM by base URL), and `mock` (deterministic scripted responses used by vitest and the k6 `ai-proxy` scenario, including a fragmented tool call). `LLM_PROVIDER` selects one at boot; an unknown value fails env validation listing the registered ids. `apps/server/src/ai/transports/` holds the parallel `VoiceTransport` seam with `agora-convoai` and `text`.
- **Privacy, retention, erasure:** `lib/pii.ts` `redact(text)` masks emails, Indian phone numbers, UPI handles and card-like digit runs, applied before persisting transcripts, chat and AI messages when `PII_REDACTION=true`. `PRIVACY_MODE=strict` stops persisting transcript and AI message bodies (counts and tool names only, so analytics still work), requires viewer recording consent before video renders, and is reported by `GET /api/config`. The retention loop purges transcripts, recordings (file on the shared volume + row) and analytics past their windows. `DELETE /api/me/data` executes the cascade/tombstone contract declared in the data model, in one transaction. Residency: `CONVOAI_GEOFENCE_AREA` plus the RTC/RTM geofencing options named in `docs/production-considerations.md`.
- **Webhooks and observability:** `routes/webhooks.ts` `POST /api/webhooks/agora` verifying `Agora-Signature-V2` (HMAC-SHA256 over the raw body; `express.raw` on that route), replying 200 well inside 10 s and processing asynchronously. Handles ConvoAI `102` (release slot, mark stopped), `110` (mark failed, release slot), `111` (metrics), and Cloud Recording `31` / `1` / `11`. Because Agora states NCS delivery is not guaranteed, the lease sweeper and `query` polling remain primary. `GET /metrics` (Prometheus) and `GET /api/health` (`{status, db, redis, version}`) — nginx's upstream check and k6's warm-up probe. Every log line carries `requestId`; AI paths add `conversationId`, `agoraAgentId`, `channel` and `provider`, so a failure can be traced across Agora Console / Call Inspector, the AI provider and our services.
- **Cloud Recording implementation:** `agora/recording.ts` — `startRecording` (`acquire` with recorder uid from the sequence and `scene:0`, then `mode/mix/start` with `avFileType:["hls","mp4"]` and env `storageConfig`), `query` polling every 30 s from the background process (Agora's guidance: `start` 200 ≠ recording), `stopRecording` (`mode/mix/stop`, read `fileList`, set `recordingUrl`, `recordingStatus='ready'`, publish `recording.ready`). `RECORDING_PROVIDER=auto` uses Agora when all `RECORDING_STORAGE_*` are present, else the browser path from Stage 3; `off` disables both. ### Stage 7 — Scale implementation and proof

**Gate: the scale primitives are running in a two-replica stack and a deterministic k6 suite measures them.**

- **Chat sharding at load:** the load session is seeded with `expectedPeakViewers:300`; with `RTM_CHAT_SHARD_TARGET=2` that clamps to **49 shards**, exercising both the clamp and the host's bounded fan-out (49 REST publishes per host message) while staying under the 50-channels-per-client subscription limit.
- **Delivery-tier transition (decision 8):** `agora/mediapush.ts` — `createConverter(session)` → `POST https://api.agora.io/{MEDIA_PUSH_REGION}/v1/projects/{appId}/rtmp-converters`, transcoded 720p / 1500 Kbps / H.264 targeting `MEDIA_PUSH_RTMP_URL + '/' + slug`; store `mediaPushConverterId` and `mediaPushStatus`; `hlsUrl = MEDIA_PUSH_HLS_URL + '/' + slug + '.m3u8'` with `hlsOriginKind='media-push'`; `deleteConverter` on end. The rtc→cdn flip is a Redis Lua compare-and-set on `session:<id>:deliveryTier`; the winning caller publishes `session.delivery_tier_changed` once, clients start HLS **before** leaving the live RTC channel, and the tier never returns to `rtc`. With `MEDIA_PUSH_ENABLED=false`, `hlsUrl` falls back to `SAMPLE_HLS_FALLBACK_URL` with `hlsOriginKind='simulated-origin'`, and **every surface — UI badge, API response, README and analytics — says `simulated-origin`.** `RTC_TIER_MAX_VIEWERS` defaults to **3** so the transition is observable with three tabs; the load stack sets **150** so the transition happens mid-run rather than at the first join.
- **Two replicas:** `api1`/`api2` behind nginx, shared recordings volume, one Redis subscriber per process, all timers in `background` — the properties that tests A13/A14 and scenario L2 actually measure.
- **Deterministic load fixtures.** `loadtest/seed.ts` creates **600 load-only users** (`load+<n>@loadtest.invalid`, never the three demo personas), pre-populates their Redis sessions, writes gitignored `loadtest/.generated/sessions.json`, creates a dedicated **high-stock checkout variant**, a separate **oversell variant with stock exactly 100**, and **100 `aiConversations` rows (`status:'running'`, far-future `callbackExpiresAt`, a load `userId`, the load session's `liveSessionId`) written to `loadtest/.generated/conversations.json`, so L6 mints valid signatures from `CONVO_LLM_SHARED_SECRET` against real conversations instead of measuring a 404 path**. `loadtest/reset.ts` resets stock, carts, poll votes, viewer presence, promotion redemptions, Redis-stream consumer state **and the load session's one-way state — `liveSessions.deliveryTier='rtc'`, `session:<id>:deliveryTier`, `session:<id>:status='live'`, `session:<id>:viewers` — so L2 and A15 observe a fresh `rtc → cdn` transition on every run rather than only the first**, and is run before **each** scenario.
- **k6 scenarios** (`loadtest/k6/`, `brew install k6`), against the 2-replica nginx stack:
  - **L1 `browse.js`** — 200 VUs for 60 s over `GET /api/products` (mixed facets) and `/api/products/:slug`, unauthenticated. `p(95) < 200 ms`, unexpected HTTP failures `< 1%`. The generator runs from a `RATE_LIMIT_TRUSTED_CIDRS` address so the shared-IP bucket does not distort the measurement; per-user buckets are never bypassed.
  - **L2 `live-join.js`** — 300 authenticated VUs, join + 5 heartbeats each. `p(95) < 250 ms`; asserts **exactly one** `rtc → cdn` transition and that every subsequent join reports the CDN tier.
  - **L3 `engagement.js`** — 300 VUs for 60 s; each VU sends **one chat and one reaction per second and one poll vote in total**. That is ≤ **300 RTM REST publishes/s** (60% of the 500 req/s per-App-ID default, leaving headroom for host fan-out and moderation) and ≈ **600 analytics events/s** against a **2,000 rows/s** configured drain. Asserts HTTP `p(95) < 250 ms`, analytics backlog `< 2,000` at test end and `0` within 15 s. Chat and reaction budgets (120/min each) are set exactly to accommodate this profile.
  - **L4 `checkout-burst.js`** — `ramping-arrival-rate` 50 → 200 iterations/s over 30 s against the high-stock variant, each iteration add-to-cart + `POST /api/orders` with a fresh per-user `Idempotency-Key`. `p(95) < 750 ms`, unexpected failures `< 2%`. The linear ramp yields ≈3,750 iterations ⇒ ≈6 orders per load user in 30 s ⇒ ≈12.5 orders/min/user, comfortably inside the 60/min budget. The 200 ms pre-authorization delay occurs **outside** database transactions.
  - **L5 `oversell.js`** — 500 unique users race for the stock-100 variant: exactly **100** paid orders, **400** `409 out_of_stock`, final stock **0**, and no duplicate `(userId, idempotencyKey)`. Correctness, not latency.
  - **L6 `ai-proxy.js`** — 100 VUs posting Agora-shaped bodies with valid signed headers at `/api/ai/convo/:conversationId/chat/completions` with `LLM_PROVIDER=mock`, isolating proxy + tool-execution overhead from model latency. `p(95)` time-to-first-SSE-chunk `< 150 ms`; the script includes **one fragmented tool call** and **one replayed callback request for an already-executed `turn_id`** to prove index accumulation and `aiToolCalls` deduplication.
  - `npm run loadtest` runs `reset` + all six and writes `loadtest/results/summary.json`.
- **How the results are described.** These are **local scale and component evidence** — they prove sharding, the one-way tier transition, stateless routing across two replicas, no-oversell under contention, and drain headroom on the hardware named in the results table. They are **not** "Big Billion Days capacity proven". `docs/scale-and-capacity.md` extrapolates the bottlenecks and names the Agora quotas that need a support ticket first; the measured table reports hardware, replica count, offered rates, `p(95)`, error rates and stream backlog.

## Assumptions & contingencies

- Every optional extension, the seller dashboard, the load-tested scale primitives and the follow-up-change seams are **required scope**, because the user added them. The stage gates change sequencing and correctness, never the requested outcomes.
- Available credentials are Agora App ID / certificate / customer credentials with ConvoAI enabled, plus OpenRouter. **No** OpenAI (or other TTS/ASR) vendor key, **no** CDN RTMP/HLS origin, **no** object-storage bucket. Nothing in this plan requires one.
- **Managed-mode TTS availability for this specific project is confirmed only by smoke check S6.** If `join` rejects managed `openai`/`tts-1`, switch to Agora-managed MiniMax `speech-2.8-turbo`. Do **not** introduce a BYOK key this project does not have, and do not switch to ElevenLabs (BYOK-only, paid plan required).
- **ARES lists `en-US`, `hi-IN` and `es-ES` as supported.** If a project-specific entitlement rejects one at `join`, attempt managed Deepgram `nova-3` with the mapping `en-US → en`, `hi-IN → hi`, `es-ES → es` and record the provider response. Only if both fail does that language fall back to captions-only, and the README says so. Text input is a degraded transport, never evidence of multi-language voice.
- **`remote_rtc_uids` docs say one uid; the official demo uses `["*"]`.** The plan sends the single viewer uid, matching the documentation. If `join` rejects it, send `["*"]` — the channel is private, so the distinction is harmless.
- **If ConvoAI `join` fails for any environmental reason**, `CONVOAI_ENABLED=false` makes `/start` return `503 ai_capacity` and the assistant runs entirely on the labelled text transport against the identical tool executor. The commerce journey, promotions and add-to-cart demo stay intact.
- **If ngrok is unavailable**, deploy the API anywhere with a public HTTPS URL and set `PUBLIC_API_URL`. Do not substitute a Cloudflare quick tunnel — it does not support SSE.
- **Media Push needs a CDN ingest URL and HLS origin that do not exist here.** `MEDIA_PUSH_ENABLED=false` plus the `simulated-origin` fallback keeps the tier transition and the HLS handoff demonstrable; setting the three `MEDIA_PUSH_*` vars exercises the real converter API with no code change. The end-to-end check (M16) stays **`unverified — external RTMP/HLS origin required`**.
- **Cloud Recording needs a bucket.** `RECORDING_PROVIDER=auto` therefore uses host-browser capture, which is the artifact the demo plays; supplying `RECORDING_STORAGE_*` switches to the real Agora pipeline with no code change, and that path stays **`unverified — third-party bucket required`**.
- **Chat throughput is bounded by the default 500 REST req/s per App ID.** The prototype proves sharding, server-authoritative moderation and stateless routing below that line. Higher throughput needs an Agora quota increase and a dedicated publisher/moderation tier; 49 shards alone prove nothing about millions of moderated publishers.
- **`RTC_TIER_MAX_VIEWERS=3` and `RTM_CHAT_SHARD_TARGET=2` are demo values** chosen so the behaviour is visible with a few tabs (the load stack keeps `RTM_CHAT_SHARD_TARGET=2` with `expectedPeakViewers:300`, which _clamps to_ 49 shards, and raises `RTC_TIER_MAX_VIEWERS` to 150 — 49 is a computed result, never a target value). Production values are derived in `docs/scale-and-capacity.md`; never present demo numbers as production thresholds.
- **PSTN is designed, not built** — no phone number or SIP trunk is available. The seam is real and exercised by L6.
- Payment pre-authorization, serviceability, tax/shipping, refunds and seller onboarding approval are mocked or omitted per the brief's pragmatic clause, and each is listed in the README's "what is mocked and why".
