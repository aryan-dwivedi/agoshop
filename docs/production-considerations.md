# Production considerations

What this prototype already does correctly, and what it would need before it carried real users and real money. Every row names the file that implements it, so the two halves can be told apart without reading the whole tree.

Two labels are carried verbatim from the plan wherever they are relevant, because neither path has been exercised against real infrastructure: **Media Push end-to-end is `unverified — external RTMP/HLS origin required`** and **Agora Cloud Recording against a bucket is `unverified — third-party bucket required`**. PSTN is designed and its seam is exercised without a browser, but **not built** — there is no phone number or SIP trunk.

Scale numbers, measured load results and the capacity model are not repeated here; they live in `docs/scale-and-capacity.md`.

## 1. Security

### Implemented here

| Control                                         | Where                                                                                                                                                                                                                                                                                                                       | What it actually buys                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The App Certificate never leaves the server** | `agora/tokens.ts` mints every RTC/RTM token; `routes/config.ts` returns only `agoraAppId`, `chatServiceAccount`, `supportedLanguages`, `privacyMode`, `features`; the browser bundle holds no Agora secret and calls the API on same-origin relative paths (`apps/web/vite.config.ts` proxies `/api` and `/media` to nginx) | A leaked browser bundle cannot mint a token. Channel access is a server decision on every join, including the combined RTC+RTM token minted for the ConvoAI agent (`mintAgentRtcRtmToken`)                                                                                                                                                                                                                                             |
| **Per-conversation HMAC on the AI callback**    | `ai/callbackAuth.ts`                                                                                                                                                                                                                                                                                                        | `signature = base64url(HMAC-SHA256(CONVO_LLM_SHARED_SECRET, "<conversationId>.<expires>"))`, recomputed over the conversation id **in the request path** and compared with `crypto.timingSafeEqual`. Stale (`expires <= now`) and absurd-future (`> MAX_FUTURE_SKEW_SECONDS`, 24 h) expiries are both refused; every failure is a flat `401 invalid_callback_signature` with the reason logged server-side, so a prober learns nothing |
| Second expiry bound                             | `ai/completionsRoute.ts` (`expires_beyond_conversation`)                                                                                                                                                                                                                                                                    | A signature may not outlive the conversation's own `callbackExpiresAt`, even if the header itself is in range                                                                                                                                                                                                                                                                                                                          |
| `Authorization` is never consulted              | `ai/callbackAuth.ts`, `agora/convoai.ts`                                                                                                                                                                                                                                                                                    | The same signature is placed in `llm.api_key` only because Agora may require a non-empty key there, and Agora's auth-header format for that field is undocumented. Authorization reads `X-Convo-Expires` + `X-Convo-Signature` and nothing else                                                                                                                                                                                        |
| Opaque session ids, records in Redis            | `middleware/session.ts`                                                                                                                                                                                                                                                                                                     | 32 random bytes, `base64url`, in a **signed httpOnly cookie** (`SameSite=Lax`, `secure` in production), record at `sess:<id>` with a 7-day sliding TTL. Replicas stay stateless _and_ revocation is immediate                                                                                                                                                                                                                          |
| Role guards                                     | `middleware/session.ts`                                                                                                                                                                                                                                                                                                     | `requireAuth`; `requireRole('seller'\|'admin')` for `/api/seller/*` and `/api/admin/*`; `requireSessionHost` for start/end/pin/poll/moderation — admin passes, a seller passes only for a session whose `hostUserId` is theirs                                                                                                                                                                                                         |
| Ban split, deliberately                         | `routes/tokens.ts`, `domain/chat.ts`                                                                                                                                                                                                                                                                                        | `POST /api/rtc/token` and `POST /api/rtm/token` are refused only on `users.bannedAt` / `deletedAt`. A _session-scoped_ chat ban does not refuse them (that RTM client also carries AI transcripts and chat reads); it is enforced at `POST /api/sessions/:id/chat` → `403 chat_blocked`, i.e. where publishing actually happens                                                                                                        |
| Rate limiting                                   | `lib/ratelimit.ts`                                                                                                                                                                                                                                                                                                          | Redis token bucket in Lua so refill-and-take is atomic. Budgets in `BUDGETS`: products 600/min/user + 1200/min/IP, cart 120, chat 120, reactions 120, poll vote 10, `POST /api/ai/conversations` 10, orders 60, login 10                                                                                                                                                                                                               |
| Server-authoritative pricing                    | `domain/orders.ts`, `routes/orders.ts`                                                                                                                                                                                                                                                                                      | The order body accepts `paymentMethod`, `pincode` and an optional `card` — **no amounts at all**. `createOrder` prices the cart itself via `resolveLineContext` + `evaluatePromotions`, then re-prices _inside_ the transaction. `cartItems.unitPriceMinorUnits` is a display snapshot and is never authoritative                                                                                                                      |
| Webhook verification                            | `routes/webhooks.ts`, `app.ts`                                                                                                                                                                                                                                                                                              | HMAC-SHA256 over the **raw** body (`express.raw({ type: '*/*', limit: '1mb' })` mounted on that path only) compared to `Agora-Signature-V2` with `timingSafeEqual`. With `AGORA_WEBHOOK_SECRET` unset the endpoint answers `503 webhook_not_configured` rather than accepting unsigned callbacks                                                                                                                                       |
| Log redaction                                   | `lib/logger.ts`                                                                                                                                                                                                                                                                                                             | `authorization`, `cookie`, `x-convo-signature`, `*.api_key`, `*.secretKey`, `*.accessKey`, `passwordHash`, `password`                                                                                                                                                                                                                                                                                                                  |
| Origin allowlist                                | `app.ts`                                                                                                                                                                                                                                                                                                                    | `cors({ origin: WEB_ORIGIN.split(','), credentials: true })`; `x-powered-by` disabled                                                                                                                                                                                                                                                                                                                                                  |
| Config refuses to be wrong                      | `env.ts`                                                                                                                                                                                                                                                                                                                    | One `zod` schema parsed at boot; an invalid `DATABASE_URL` or an unknown `LLM_PROVIDER` prints field-level errors and `process.exit(1)`. No lazy `process.env` reads anywhere else                                                                                                                                                                                                                                                     |
| Bounded proxy trust                             | `app.ts`, `env.ts`, `render.yaml`, `infra/Caddyfile`                                                                                                                                                                                                                                                                        | Express trusts only the Caddy hop on Render instead of arbitrary forwarding headers. Caddy preserves the client address supplied by Render's ingress while API, AI, and SSE remain private services.                                                                                                                                                                                                                                   |
| Render TLS edge                                 | `render.yaml`, `infra/Caddyfile`, `infra/Dockerfile.edge`                                                                                                                                                                                                                                                                   | Render terminates TLS and redirects HTTP; Caddy sends HSTS, `nosniff`, frame denial, and a strict referrer policy, serves immutable hashed frontend assets, and routes backend traffic over Render's private network.                                                                                                                                                                                                                  |

**Why a global shared secret was rejected.** A single bearer token in `llm.api_key` (or in `Authorization`) authorizes _every_ conversation for as long as it exists, and it leaks from the widest possible surface: Agora's stored agent configuration, its logs, and every proxy in between. The per-conversation HMAC has neither property — a captured signature authorizes exactly one `conversationId` and dies at `expires` — and it needs no per-key server state, because the signature is _derived_, not stored. The signing key stays on the server; Agora only ever holds a derivative of it.

### Would need work

| Gap                                 | What production adds                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Secret management**               | The Render Blueprint stores generated and operator-supplied secrets in an environment group instead of a repository file. A higher-assurance production environment still needs KMS/Vault-backed rotation. `CONVO_LLM_SHARED_SECRET` rotation specifically needs a key id (`X-Convo-Key-Id`) and an overlap window, or every in-flight agent's signature breaks; `AGORA_APP_CERTIFICATE`, `AGORA_CUSTOMER_SECRET`, `AGORA_WEBHOOK_SECRET`, and `LLM_API_KEY` need the same treatment |
| **CSRF posture for cookie auth**    | Today: `httpOnly` + `SameSite=Lax` + a signed cookie + a `WEB_ORIGIN` CORS allowlist, and `POST /api/orders` additionally requires a custom `Idempotency-Key` header (which forces a preflight). That is not a defence in depth — there is no anti-CSRF token and no explicit `Origin`/`Sec-Fetch-Site` check on mutations. Production adds a double-submit or synchronizer token on every state-changing route, or `SameSite=Strict` plus a bearer-in-memory scheme                 |
| **Proxy topology changes**          | `TRUST_PROXY_HOPS` is deployment-specific. Any additional CDN or load balancer must update this count and configure its edge to discard untrusted forwarding headers; otherwise client IP attribution is wrong or spoofable.                                                                                                                                                                                                                                                         |
| **Managed edge protection**         | Render supplies TLS termination and DDoS protection, and the Caddy edge supplies baseline security headers, but there is no application WAF, bot management, or application-specific CSP. Production puts managed controls in front of `/api/auth/*`, `/api/orders`, and `/api/webhooks/agora`, and derives a tested CSP from the Agora/media origins the browser actually uses.                                                                                                     |
| **Supply chain**                    | No CI, so no `npm audit`/Dependabot/SBOM gate and no image scanning. The pinned Agora/OpenAI SDK versions are checked into `package.json` but nothing watches them                                                                                                                                                                                                                                                                                                                   |
| **Account security**                | `bcryptjs` cost 10, no MFA, no password reset, no account lockout beyond the 10/min login bucket                                                                                                                                                                                                                                                                                                                                                                                     |
| **The mock pre-authorizer must go** | `domain/mock/payments.ts` is in-process: a 200 ms delay, a deterministic decline for a card ending `0000`, and a `voidPreauthorization` that only logs. **No money is real and no external call is made.** Before any money is real this is a PSP integration, and the moment it is, the reliability item below (a database rollback cannot reverse a charge) stops being theoretical                                                                                                |

## 2. Reliability

### Implemented here

| Property                                        | Where                                                       | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Conditional, idempotent session transitions** | `domain/sessions.ts`                                        | `startSession`: `UPDATE live_sessions SET status='live', startedAt=now(), chatShardCount=$n, deliveryTier='rtc' WHERE id=$id AND status='scheduled' RETURNING *`. `endSession` is the mirror on `status='live'`. Only the row-winning caller writes `session:<id>:status`, publishes `session.status_changed`, freezes the shard count and starts side services; a loser reports the observed state (`session_not_startable` / `session_not_live`) instead of double-acting                                                                                                                                                                                 |
| **Side-service status isolation**               | `domain/sessions.ts`                                        | Recording, RTT and Media Push start under one `Promise.allSettled`; each writes its own `recordingStatus` / `rttStatus` / `mediaPushStatus` (with `recordingError` for the reason) and a rejection is logged only. A broken side service never rolls back a working RTC session                                                                                                                                                                                                                                                                                                                                                                             |
| **Pre-authorize outside the transaction**       | `domain/orders.ts`                                          | Order is: price server-side → validate `checkoutPolicy` → `preauthorize` **with no transaction open** → one short transaction. No row lock is ever held across the payment call's latency                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **`409 pricing_changed` and the void path**     | `domain/orders.ts`                                          | Inside the transaction the cart is re-priced (`priceCart(userId, now, tx)`); if the total no longer equals the pre-authorized amount — most often because the session ended and `LIVE20` dropped — it aborts with `409 pricing_changed` carrying the new totals. **Every** abort, including `409 out_of_stock` and `below_min_order`, runs `voidPreauthorization(preauth.paymentRef)` in the `catch`                                                                                                                                                                                                                                                        |
| **Atomic stock decrement**                      | `domain/orders.ts`                                          | `update product_variants set stock = stock - $qty where id = $id and stock >= $qty returning stock`; zero rows returned ⇒ `409 out_of_stock`. No read-then-write anywhere, so overselling is structurally impossible                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Idempotent writes**                           | `lib/idempotency.ts` + `UNIQUE (userId, idempotencyKey)`    | `Idempotency-Key` is required on `POST /api/orders` (`idempotency_key_required`). A Redis `SET NX` claims the key for 24 h; a replay returns the stored status+body with `Idempotent-Replay: true`; a concurrent duplicate gets `409 idempotency_in_progress`; a failed attempt deletes the key so it is not poisoned. Keys are per user, so two users may legitimately send the same text                                                                                                                                                                                                                                                                  |
| **Tool-call idempotency**                       | `aiToolCalls` PK `(conversationId, turnId, name, argsHash)` | A retried Agora callback re-runs the model and therefore mints a _fresh_ `tool_call_id` — keying on that id would dedupe nothing. Keying on the argument hash makes a replayed callback return the stored result instead of adding to the cart twice                                                                                                                                                                                                                                                                                                                                                                                                        |
| **ConvoAI lease semaphore + sweeper**           | `ai/admission.ts`, `background.ts`                          | Redis sorted set `ai:agents` scored by lease expiry; one Lua script prunes expired leases and `ZADD`s only while `ZCARD < CONVOAI_MAX_CONCURRENT_AGENTS` (a check-then-add from two replicas would both pass). Lease TTL is `CONVOAI_IDLE_TIMEOUT_SECONDS + 60`, refreshed by the client heartbeat, so a crashed tab's slot is reclaimed. `expiredLeases()` is deliberately non-destructive: the 30 s sweeper calls Agora `leave` _first_, then releases, so a crash mid-sweep retries instead of orphaning a billable agent. Exhaustion is `503 ai_capacity` with a computed `retryAfterSeconds`, and the client falls back to the labelled text transport |
| **NCS webhooks are not load-bearing**           | `routes/webhooks.ts`                                        | Agora requires a 200 within 10 s, retries three times, then **drops** the event, and states core flows must not depend on NCS. So the route acknowledges first and processes in `setImmediate`, and the primary mechanisms stay local: the lease sweeper for agents (30 s) and Cloud Recording `query` polling (30 s) from `background.ts`. Webhooks only make convergence faster — `102` releases the lease, `110` marks failed, `111` is recorded as an `ai_agent_metrics` analytics event, `31`/`1`/`11` update the recording                                                                                                                            |
| No double-emitted aggregates                    | `background.ts`                                             | One process owns every timer and stream consumer; each loop reschedules only after its own body settles, so a slow tick cannot overlap itself                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Durable deferred work                           | `background.ts`                                             | `analytics:events` and `jobs:session-summary` are Redis streams with consumer groups; `readBatch` also claims what a dead consumer left pending, and entries are `XACK`'d/deleted only after the durable write                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Explicit, non-lying failures                    | `agora/convoai.ts`, `agora/tokens.ts`                       | `AbortSignal.timeout(20_000)` on ConvoAI (15 s recording, 5 s signaling publish); documented `422 ResourceQuotaLimitExceeded` / `429` become `503 ai_capacity`; unreachable becomes `502 convoai_unreachable`; a `leave` for an agent that already left tolerates `404`; missing customer credentials return `503 convoai_unconfigured` rather than sending `Basic Og==` and misreading a 401 as a product failure                                                                                                                                                                                                                                          |

### Would need work

| Gap                                      | What production adds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agora dual REST domains and backoff**  | This is the honest state: `AGORA_REST_BASE` is derived from a single `AGORA_API_BASE` (default `https://api.agora.io`), and `agora/tokens.ts` documents `api.sd-rtn.com` as the failover host — but **no automatic failover, retry or backoff is implemented**. Every Agora call is a single attempt with a timeout. Production adds jittered exponential retry on `429`/`5xx`, rotation between the two documented domains, a circuit breaker so a degraded Agora region does not consume the request pool, and client-side pacing for Cloud Recording's documented 10 QPS per App ID |
| **Async payment pipeline**               | Checkout is synchronous behind the atomic decrement. Production splits it into authorize → stock reservation → capture/void with an **expiry reconciler** for reservations whose capture never arrived. A database rollback cannot undo an external charge, which is why the compensating `void` has to be a durable job rather than a `catch` block. Designed in `docs/scale-and-capacity.md`                                                                                                                                                                                         |
| **Replica draining**                     | `GET /api/health` reports `db`/`redis` individually and answers `503 degraded`, and nginx has `max_fails=3 fail_timeout=10s` — but there is no liveness/readiness split, and `index.ts` shutdown calls `server.close()` then exits, so in-flight SSE connections and streaming AI callbacks are cut rather than drained. Production adds a readiness gate that fails first, a drain window sized to the SSE heartbeat, and `SIGTERM` handling that lets open streams finish                                                                                                            |
| **Backpressure on the analytics stream** | `lib/analytics.ts` `track()` is a fire-and-forget `XADD` with no `MAXLEN` and no shed path; a stalled background process grows the stream until Redis memory is the limit. `analytics_stream_backlog` makes it visible but nothing acts on it. Production caps the stream (`MAXLEN ~`), sheds low-value event types above a watermark, and alerts on backlog growth rather than absolute size                                                                                                                                                                                          |
| **DR and backup**                        | None. Postgres and Redis are Compose volumes and the recordings volume is a local shared mount. Production needs PITR backups with a tested restore, a Redis persistence/replication decision (session loss = mass logout; lease loss = temporary over-admission until the sweeper converges), object storage for recordings with lifecycle rules, and a documented RPO/RTO                                                                                                                                                                                                            |

## 3. Privacy, consent and retention

### Implemented here

| Obligation                                   | Where                                               | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`PRIVACY_MODE=strict` as a runtime mode**  | `env.ts`, `lib/pii.ts`, `routes/config.ts`          | `persistBodies = PRIVACY_MODE !== 'strict'`. In strict mode `aiMessages.content`, `toolArgs`/`toolResult` (`ai/executor.ts`) and transcript rows (`routes/sessions.ts` — `POST /api/sessions/:id/transcript` returns `{ persisted: false }`) are not written, while counts, tool names and analytics still increment, so the seller dashboard keeps working. The mode is reported by `GET /api/config` and surfaced in the UI header (`components/Layout.tsx`)                                                                                                                                                                 |
| **`PII_REDACTION`**                          | `lib/pii.ts`                                        | `redact()` masks four patterns before anything is persisted: emails → `[email]`, Indian mobile numbers (`+91`/`0` prefix, leading 6–9, 10 digits) → `[phone]`, UPI handles on the seeded provider list (`okhdfcbank, oksbi, okaxis, okicici, paytm, ybl, upi`) → `[upi]`, and card-like runs of 13–19 digits with optional separators → `[card]`. Applied to chat (`domain/chat.ts`), captions/transcripts (`routes/sessions.ts`) and AI user/assistant text (`ai/executor.ts`)                                                                                                                                                |
| **Host recording consent before going live** | `pages/Host.tsx`, `domain/sessions.ts`              | The host console cannot go live until the consent checkbox is ticked (`canGoLive`); the winning transition writes `recordingConsentAt` and emits a `recording_consent` analytics event                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Viewer consent gating in strict mode**     | `domain/sessions.ts`, `pages/Live.tsx`              | The join response carries `recordingConsentRequired: PRIVACY_MODE === 'strict'`; the viewer's video stage stays blurred behind an acknowledgement overlay until they accept                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Retention windows + nightly purge**        | `background.ts` `runRetentionPurge`, run every 24 h | Transcripts older than `TRANSCRIPT_RETENTION_DAYS` (30) are deleted; recordings whose session ended more than `RECORDING_RETENTION_DAYS` (30) ago have the **file unlinked from the shared volume** and `recordingUrl`/`recordingStatus`/`recordingSid`/`recordingResourceId` cleared, so the purge is visible to every replica and to nginx; analytics rows older than `ANALYTICS_RETENTION_DAYS` (90) are deleted                                                                                                                                                                                                            |
| **Subject erasure in one transaction**       | `routes/me.ts` `DELETE /api/me/data`                | One transaction: deletes `wishlist_items`, `product_views`, `chat_messages`, `poll_votes`, `ai_tool_calls` → `ai_messages` → `ai_conversations`, `cart_items` → `carts`, and `chat_moderation` rows on either side; **de-identifies** `analytics_events.user_id` to `NULL`; then **tombstones** the `users` row (`deleted_at`, `email → erased+<id>@deleted.invalid`, `display_name → 'Erased user'`, empty `password_hash`, `default_pincode` nulled). `orders`, `orderItems` and `promotionRedemptions` survive against that tombstone for financial reasons, and the session is destroyed so the cookie is dead immediately |
| **Residency via geofencing**                 | `agora/convoai.ts`                                  | The ConvoAI join body sends `geofence: { area: CONVOAI_GEOFENCE_AREA }`, default `INDIA`, validated against the documented set `GLOBAL, NORTH_AMERICA, EUROPE, ASIA, INDIA, JAPAN`                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Would need work

| Gap                                                  | What production adds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A consent ledger, and a DPA**                      | Host consent is one timestamp plus one analytics event; the **viewer** acknowledgement is client-side state only (`Live.tsx`) and is never sent to the server, so there is no record that a given viewer consented, to what text, at what version, at what time. Production needs an append-only consent ledger (subject, purpose, policy version, timestamp, evidence), a withdrawal path, and a signed DPA/sub-processor list covering Agora (media, ASR, TTS, recording) and the LLM provider — voice data leaves the platform through both |
| **Retention is incomplete**                          | Only transcripts, recordings and analytics have windows. `chatMessages` and `aiMessages` (which in `standard` mode hold redacted conversation bodies) have **no** purge, and the mock-checkout `orders` are kept forever by design. Production sets a window per table, and per _purpose_, not one global default                                                                                                                                                                                                                              |
| **Per-region data residency enforcement**            | Only ConvoAI is pinned. `AgoraRTC.setArea` / the RTM geofencing options are **not wired in the web client**, and our own Postgres/Redis are single-region with no residency partitioning. Production pins RTC and RTM areas alongside ConvoAI, pins the recording bucket's region (`RECORDING_STORAGE_REGION` is plumbed but that path is `unverified — third-party bucket required`), and routes a subject's rows to their region rather than tagging them                                                                                    |
| **The legal basis for retaining transcripts at all** | Nothing in the code answers _why_ a voice transcript is kept for 30 days. That is a purpose question: performance monitoring and dispute resolution are defensible with a short window and redaction; model training is not, without separate opt-in. Production writes the purpose down per data class, drops `PRIVACY_MODE=strict` to the default for voice surfaces in strict jurisdictions, and treats "we could analyse it later" as not a basis                                                                                          |

## 4. Observability

### Implemented here

**Prometheus metrics** — `lib/metrics.ts`, exposed on `GET /metrics` (plus `prom-client` default process metrics):

| Metric                              | Type      | Question it answers                                                                                                                                                                                         |
| ----------------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ai_tool_calls_total{tool,outcome}` | counter   | Is the assistant actually executing catalog tools, and which ones fail? Incremented in `ai/executor.ts`; this is what the demo reads to prove `search_products`/`compare_products`/`add_to_cart` really ran |
| `ai_agent_slots_in_use`             | gauge     | How close is the App ID to the ConvoAI concurrency cap right now? Set from live (non-expired) leases in `ai/admission.ts` — the number that predicts `503 ai_capacity` before a user sees it                |
| `promotion_applied_total{code}`     | counter   | Which promotion codes are actually being redeemed on orders? Incremented per applied promotion in `domain/orders.ts` — the discount-attribution cross-check                                                 |
| `llm_latency_seconds{provider}`     | histogram | Is slow voice the model or us? Labelled by registered provider id, so a provider swap is comparable                                                                                                         |
| `tool_latency_seconds{tool}`        | histogram | Which tool is adding turn latency inside our own domain code                                                                                                                                                |
| `chat_messages_total{action}`       | counter   | Accepted vs `rejected` (not live, muted/banned) vs `flagged` — moderation pressure and how much of it is being refused at the door (`domain/chat.ts`)                                                       |
| `chat_rest_publishes_total`         | counter   | Our consumption of Agora's 500 REST req/s per-App-ID Signaling budget, including host fan-out across shards (`agora/signaling.ts`)                                                                          |
| `moderation_actions_total{action}`  | counter   | Mute/unmute/ban/delete volume (`domain/moderation.ts`)                                                                                                                                                      |
| `analytics_stream_backlog`          | gauge     | Is the single background drain keeping up? Refreshed by the drain itself and re-read on every scrape in `routes/health.ts`, because the drain runs in a different process from the replica being scraped    |
| `sse_clients`                       | gauge     | Live SSE connections held by _this_ process — the per-replica fan-out load (`lib/sse.ts`)                                                                                                                   |

**Tracing fields.** `middleware/context.ts` accepts or generates `x-request-id`, binds a pino child logger, and echoes the header; `lib/errors.ts`/`middleware/errorHandler.ts` return `{error:{code,message,requestId}}` so a user-visible failure maps to a log line. On the AI path `ai/completionsRoute.ts` binds a child logger with `conversationId`, `agoraAgentId`, `channel` (`ai-<conversationId>`) and `provider`, plus `turnId` — the four fields that let one failure be followed across **Agora Console / Call Inspector** (channel and agent id), **the AI provider** (provider and turn), and **our services** (request id). `X-Convo-Id` carries the same conversation id on Agora's own callback, and ConvoAI `111` performance events are ingested as `ai_agent_metrics` analytics rows.

**Health.** `GET /api/health` returns `{status, db, redis, version}` with `200`/`503` — nginx's upstream check and the k6 warm-up probe. It reports the two dependencies individually rather than a bare 200.

### Would need work

| Gap                                               | What production adds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Distributed tracing across the Agora boundary** | Correlation today is by shared identifiers, not by trace context: there is no OpenTelemetry, no span propagation, and Agora's `llm.headers` (the documented channel for "business-specific information") carries only `X-Convo-Id`/`X-Convo-Expires`/`X-Convo-Signature`. Production emits W3C `traceparent` through `llm.headers` and into the LLM provider call, so one trace spans browser → Agora → our proxy → provider → tools                                                                                      |
| **Alerting thresholds and SLOs**                  | Metrics exist; nothing alerts. The first four SLOs to write are: voice turn latency (`llm_latency_seconds` + `tool_latency_seconds`), agent admission success (`ai_agent_slots_in_use` against `CONVOAI_MAX_CONCURRENT_AGENTS`), Signaling publish headroom (`chat_rest_publishes_total` against 500 req/s per App ID), and drain health (`analytics_stream_backlog` growth rate, not level). Checkout needs an error-budget alert on `409 pricing_changed` / `402 payment_declined` rates                                |
| **Log aggregation**                               | pino writes to stdout (`pino-pretty` in development) and nothing collects it. ## 6. Scalability

Only the properties; the numbers, the measured load results and the capacity model are in **`docs/scale-and-capacity.md`**.

- **Stateless replicas.** Session records in Redis, no sticky sessions; any request may land on either replica, which is what makes the two-replica test meaningful.
- **Shared recordings volume.** One named volume mounted into both API replicas, the background process and nginx, which serves it directly — upload, replay, deletion and retention are independent of which replica handled the request.
- **One Redis subscriber per process.** `lib/sse.ts` holds a single `ioredis` subscriber and reference-counts `SUBSCRIBE`/`UNSUBSCRIBE` per user/session channel, rather than one connection per client.
- **A single timer-owning background process.** `background.ts` owns every timer and stream consumer, so aggregates are never emitted twice no matter how many API replicas run.
- **Frozen chat shards.** `chatShardCount` is computed once at the `scheduled → live` transition and never recomputed; a viewer's shard is a stable hash, so a changing viewer count cannot re-route users mid-session.
- **A one-way tier flip.** `session:<id>:deliveryTier` moves `rtc → cdn` exactly once per session via compare-and-set and never reverts, so the threshold cannot oscillate and late joiners simply read the stored tier.

**Would need work:** every property above is proven only at prototype scale on one host, and three of them have a named next step — the background process is a single point of failure that needs leader election before it can be replicated, the recordings volume needs to become object storage, and the Agora-side ceilings (ConvoAI PCU, RTM REST req/s, Cloud Recording PCW) need support tickets before any of it matters. `docs/scale-and-capacity.md` has the order and the numbers.

## What I would fix first

Five things this prototype should not go to production without, in order:

1. **Replace the mock pre-authorizer with a real PSP, behind an async authorize → reserve → capture/void pipeline with an expiry reconciler.** `domain/mock/payments.ts` makes no external call, and the moment it does, the current `catch { void }` compensation is not enough — a database rollback cannot reverse a charge. Everything else on this list is a hardening task; this one is the difference between a demo and a shop.
2. **Move every secret into a managed store, with rotation.** `AGORA_APP_CERTIFICATE`, `AGORA_CUSTOMER_SECRET`, `AGORA_WEBHOOK_SECRET`, `CONVO_LLM_SHARED_SECRET` and `LLM_API_KEY` live in a `.env` file today. Rotation for the callback secret needs a key id and an overlap window or it breaks every in-flight agent. In the same change, stop trusting `X-Forwarded-For` from anywhere (`app.set('trust proxy', true)`), because the IP rate-limit bucket depends on it.
3. **Make every Agora REST call survive Agora having a bad minute.** Retry with jittered backoff on `429`/`5xx`, rotate between `api.agora.io` and `api.sd-rtn.com`, add a circuit breaker, and pace against the documented per-App-ID quotas. Today each call is a single attempt with a timeout, and the failover domain is a comment. Pair it with a `MAXLEN` and a shed path on `analytics:events`, which currently grows without bound if the background process stalls.
4. **Close the consent and retention gaps.** Persist viewer consent acknowledgements to an append-only ledger with a policy version (they are client-side state today), give `chatMessages` and `aiMessages` retention windows, write down the legal basis and purpose per data class, and pin RTC/RTM residency the way ConvoAI's `geofence` already is.
5. **Turn the metrics into an on-call system.** Alerting thresholds and SLOs on the ten metrics that already exist, log aggregation queryable by `requestId`/`conversationId`, `traceparent` propagated through `llm.headers` across the Agora boundary, Agora Alerts and Call Inspector wired into the same rotation — and a CI pipeline with dependency scanning, plus TLS and a WAF at the edge, so none of this depends on someone reading a container log.
